# FatLine v0.2.0 beta 1

Initial installable GitHub prerelease for FatLine, the independent Android client for compatible self-hosted ThinLine/Rdio-style scanner servers.

## Included

- New blue-and-cyan FatLine radio tower launcher icon, including Android adaptive launcher support
- Archive automatically reloads the first page whenever History is opened or its scanner reconnects, preserving the active server-side filters
- Compact current playback display replaces the oversized duplicate Now Playing card; live Hold, Avoid, and Replay actions remain available
- **Play audio / Stop audio** switch: stop scanner sound without disconnecting background server/transcript monitoring; opt-in local phrase/keyword alerts can continue with the screen off while the Android foreground service remains active
- Background playback alongside other audio apps without requesting audio focus
- Tap-to-play recent calls; Replay last; buffered call queue and reconnect recovery; system/tag/channel tree and scan lists
- Multiple open or PIN-protected compatible servers, advanced server archives, and Android Auto media library
- No ThinLine-hosted analytics, account/relay traffic, advertising SDKs, or duplicate ads

## Installation

Download **FatLine-v0.2.0-beta.1-debug.apk** under this release's Assets and install it on Android 8.0 or newer. Android may request permission to install APKs from the browser or file manager.

**This is a personal/test build**, signed with FatLine's stable **CI debug test key**, not a production release key. It can update previous FatLine CI APKs signed with that same key and package ID `dev.scanrelay.app`. It is **not** suitable for Play Store production distribution.

## Known limits / verification needed

- Real-phone tests are still needed for screen-locked transcript alerts, power saving, Wi-Fi/cellular changes, replay/encrypted audio, and Android Auto
- Android may restrict background activity or notifications according to device battery and notification settings
- No automated vendor feed assignment sync; intentional vendor-hosted access restrictions remain
- Stopping audio keeps existing queued audio but drops new live audio from playback; selecting a replay resumes audible playback

Built and checked in GitHub Actions with structural validation, JVM unit tests, debug APK assembly, and signing certificate verification.
